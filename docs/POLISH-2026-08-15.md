## Escalated — not applied

- **`packages/data-access/src/lib/api/test-files/fixtures.ts` vs.
  `packages/testing/src/lib/fixtures/games.ts`** — fallow confirmed a byte-identical
  24-line `mockGames` clone between the two. Per this repo's own `CLAUDE.md` package
  table, mock fixtures belong in `testing`. Not applied: `data-access` has no existing
  dependency on `@nba-analytics-hub/testing`, and its `vitest.config.ts` has no
  path-alias resolution for workspace packages (unlike `web`'s), so wiring this up would
  mean adding a new inter-package dependency plus an nx build-order edge
  (`testing:build` before `data-access:test`) — a structural change, not a same-behavior
  cleanup. Flagging for a deliberate follow-up rather than a blind auto-apply.
- **`api/vitest.config.ts` vs. `packages/ui/vitest.config.ts` vs. `web/vitest.config.ts`**
  — fallow found 47 and 16 lines of duplicated Vitest config boilerplate across these
  three files (coverage provider/reporters/thresholds patterns). A shared base config
  would remove the duplication, but it touches the test-running infrastructure for every
  project at once — exactly the kind of build-tooling change flagged as higher-risk on
  live infra. Left as-is.
- **`predictorServiceClient.ts`'s 422 handling** — has a `// TODO: revisit 422 handling
  once the BFF maps predictor errors for callers` comment that's still accurate:
  `predict.ts`'s catch-all currently maps every predictor failure (including a
  service-side 422 "unprocessable" case) to a generic `502` with no differentiation.
  Fixing that changes the API's error-response contract, so it's a public-API-shape
  decision, not a cleanup — flagging, not touching.
- **`packages/ui/src/lib/components/ui/card.tsx`** — unused-but-tested shadcn scaffold,
  see above. Left in place as deliberate.
- Everything else `knip`/`fallow` still flag as unused dependencies (`ajv`,
  `autoprefixer`, `@babel/core`, `@babel/preset-react`, `@eslint/js`, `@nx/node`,
  `@nx/web`, `@swc/cli`, `@swc-node/register`, `@swc/helpers`, `eslint-config-prettier`,
  `eslint-plugin-jsx-a11y`, `eslint-plugin-react`, `eslint-plugin-react-hooks`,
  `typescript-eslint`, `ts-node`, `shadcn`, `fallow`, `knip`) and "unused" `tslib` in
  every package — grep-verified as false positives, not applied:
  - `tslib` is required at runtime by `importHelpers: true` in `tsconfig.base.json`; tsc
    emits `tslib` imports into compiled output that never appear in source.
  - The ESLint/Babel/PostCSS/Nx packages are consumed transitively through
    `@nx/eslint-plugin`'s composed flat configs, Nx's executors, and the Tailwind/PostCSS
    pipeline — not by name in any config file, so static analysis can't see the edge, and
    removing them risked silently breaking `nx lint`/`nx build` in a way this pass
    couldn't fully verify without the exact plugin internals.
  - `shadcn`, `fallow`, `knip` are CLIs, not imports — expected to show up as "unused."
- Did not run `npm audit fix` — 86 pre-existing vulnerabilities (mostly transitive) are
  out of scope for a maintainability pass and `--force` would pull in breaking version
  bumps; flagging for a dedicated dependency-upgrade pass instead.
- Did not touch the root `package.json` `"type": "module"` gap that makes
  `tools/coverage-summary.js` reparse with a perf warning — root has no `"type"` field,
  and setting one affects module resolution for every plain `.js` file under the repo
  root, which is a broader change than this pass's risk budget for a cosmetic warning.
